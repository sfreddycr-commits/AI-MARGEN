# Riesgos de multi-tenancy y mitigaciones

| #   | Riesgo                                                                         | Mitigación                                                                                                                                                           | Verificación                                     |
| --- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| R1  | Un SP olvida filtrar por `tenant_id`                                           | Convención: todo SP de negocio recibe `p_tenant_id` primero; `pnpm db:check` (regla C7) exige `p_tenant_id` como primer parámetro en SPs que tocan tablas con tenant | CI + pruebas cross-tenant                        |
| R2  | El frontend envía un `tenant_id`                                               | El esquema Zod no acepta `tenant_id`; las rutas lo toman del JWT                                                                                                     | Prueba: enviar `tenant_id` ajeno no tiene efecto |
| R3  | Enumeración / adivinación de IDs                                               | Solo se exponen UUID; los SP buscan por `(tenant_id, uuid)`                                                                                                          | Prueba: UUID de B con sesión de A → 404          |
| R4  | FK que apunta a una fila de otro tenant (ej. receta de A con ingrediente de B) | Los SP resuelven UUID → id filtrando por tenant; FKs compuestas `(tenant_id, id)` en tablas hijas                                                                    | Prueba de inserción cruzada → error              |
| R5  | Cache IndexedDB de otro usuario en el mismo dispositivo                        | Base IndexedDB por `tenant+user`; borrado total en logout                                                                                                            | Prueba E2E                                       |
| R6  | IA lee datos de otro tenant / prompt injection                                 | Gateway inyecta tenant desde la sesión; herramientas sin parámetro tenant                                                                                            | Pruebas IA (SOP §39)                             |
| R7  | Reportes/exportaciones descargables por URL                                    | Archivos con clave por tenant, descarga vía endpoint autenticado, sin URLs públicas permanentes                                                                      | Prueba cross-tenant de descarga                  |
| R8  | Panel admin accesible por admins de tenant                                     | Guard `super_admin` en `/admin` (API y web)                                                                                                                          | Prueba con `tenant_admin` → 403                  |
| R9  | Logs con datos sensibles de otro tenant                                        | Logs con `tenant_uuid`, `request_id`; redacción de campos sensibles                                                                                                  | Revisión de config pino                          |
| R10 | Jobs en segundo plano sin contexto de tenant                                   | Todo job lleva `tenant_id` en su payload y lo pasa a los SP                                                                                                          | Pruebas de jobs (Etapa 10+)                      |
